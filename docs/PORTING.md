# PORTING.md — C++ → Rust module ledger

This file is the **single source of truth** for port status.
Update it **in the same commit** as the code it describes — see
`AGENTS.md` §5 and §7.

Upstream: `libtorrent` @ `v2.1.2-45-gc019e80ef`
(local checkout `D:\Projet\libtorrent\libtorrent` — read-only).

## Status legend

| Status | Meaning |
|---|---|
| `not started` | C++ identified, no Rust code |
| `in progress` | Someone is actively porting it |
| `ported` | Rust code complete, ported unit tests pass |
| `verified` | Wire-format / integration test against C++ or live swarm |
| `won't port` | Deliberately skipped — reason required |
| `n/a` | Build system / platform shim, no Rust equivalent |

C++ `*.cpp` files are listed with their primary header in parentheses
when names differ. `aux_*` headers live in `include/libtorrent/aux_/`.

## bitdaemon-disk

> **Fidelity is the point here** (ADR-0009): this subsystem is the
> primary motivation for the port. Do not simplify away the job queue,
> fences, bounded buffer pool, lazy file pool or part-file — they are
> the fixes for real production failures. Deferred-error semantics
> (lazy open → error at first I/O, as alert) are upstream-specified
> behavior, not a bug.

## Intentional deviations log

Record here every place the port *deliberately* diverges from C++
behavior (with reason).

| Where | Deviation | Reason |
|---|---|---|
| `common::version` | Reports `BitDaemon/<crate version>`, not `libtorrent/x.y` | fingerprint honesty — a client claiming to be libtorrent would be blamed for our bugs on the wire |
| `net::receive_buffer` | Ported but dormant — the engine read pump uses an equivalent `BytesMut` arena + `decode_next` | tokio codec already owns the buffering layer; the ported module stays for tests/reuse |
| `net::ip_notifier` | Polling-diff via `if-addrs` instead of netlink/`WM_NOTIFY` events | unsafe-free; change detection latency = poll cadence (session tick) instead of kernel push |
| `net::peer_alloc` | Accounting/limits only — upstream's slab pool unported | Rust `Vec`-backed peers need no arena; the counters still feed `session_stats` |
| `disk::file_progress::init` | Takes the have-pieces `Bitfield` instead of a `piece_picker` ref | dependency direction (disk ↛ session); same inputs, documented at call site |
| `disk::file::posix::fallocate` | Solaris `F_ALLOCSP64` not ported (`#elif` chain collapses to no-op) | `libc` exposes no Solaris path from a unix target; file stays `ftruncate`-sized |
| `disk::PreadDiskIo` | Extra `flush_pool` (default 1 thread, `--flush-threads`) | upstream splits only generic/hash; a single flush writer avoids concurrent seeks on rotating disks. `0` = upstream (Flush rides the generic pool) |
| `disk::PreadDiskIo` hash path | No incremental write-side hashing — upstream's `try_hash_piece`/`pending_hasher`/`drain_v2_hash_queue`/`wait_for_v2_queue` machinery is absent | our `hash` job computes the whole piece at request time over the cache overlay (+ `block_hash`es stored at flush): identical hash results, CPU spent on the hash pool at request time instead of incrementally on write arrival |
| `disk::PreadDiskIo` hash-job wait | `has_write_job` blocks mid-flush → bounded spin (400 ms) inside `hash_job` | upstream re-queues via `job_deferred`/`wait_for_v2_queue`; ours polls on the hash worker — bounded, proceeds to a normal (possibly failed) hash rather than hanging the queue |
| `disk::storage` `open_mode_extra` | Settings snapshotted per storage + `DiskIo::set_open_mode_extra` push, instead of live `settings_interface` reads | `DiskIo` trait boundary; apply_settings re-pushes to all live storages |
| `session::peer_connection_handle` | Actor commands instead of a C++ handle object | ADR-0001 actor model — same call surface, different mechanism |
| `union_endpoint.hpp` | `SocketAddr`-only endpoints (no tracker/http variant) | tracker/http fields handled at call sites — the C++ variant is never needed |
| `version`/`platform` | `acquire_manage_volume_privs` links `advapi32` statically | upstream late-binds via `get_library_procedure` for WinRT compat — unsupported target anyway |
| `session` apply_settings | `pe_settings` derived live from `settings_pack` enc knobs | upstream 2.x syncs the deprecated struct the same way |
| `session` torrent_status | `TorrentStatus` is a field subset of upstream's | snapshot covers the consumers' fields; extend on demand |
| `session::session_state` | `.session` container `{torrents: {ih: resume-blob}, dht}` is a BitDaemon extension, not an upstream format | upstream `.session` = raw `session_params` dict (torrent resume data lives in separate `.resume` files); we embed per-torrent resume blobs so a single file restores a swarm — the embedded dicts themselves are upstream-shaped and verified byte-exact |
