### Fixed

- **Peer-wire `hash_request` no longer panics on hostile descriptors
  (audit A01)**: `Torrent::on_hash_request` now runs
  `hash_picker::validate_hash_request` before touching the merkle
  trees — negative `base`/`index`/`count`/`proof_layers`, `count >
  8192` and out-of-level ranges get a `hash_reject` instead of a
  `usize` underflow/OOM (`bt_peer_connection.cpp:1199` parity).

- **`on_hashes` validates before matching and kills bad payloads**:
  an invalid hash descriptor is `invalid_hashes` (peer_error
  disconnect) even with no outstanding request, and a payload that
  `add_hashes` rejects now disconnects `invalid_hashes` instead of
  leaving the peer alive (`bt_peer_connection.cpp:1262`, `1302`).

- **Sub-header `hashes` frames (< 49 B) are consumed silently**:
  decode yields `PeerMessage::Malformed` — counted
  `num_incoming_extended`, connection stays up — matching
  `on_hashes`' `recv_buffer.size() < header_size → return` leg
  (same shape as `on_piece` < 9 B).

- **Bitfield size is now exact**: with metadata, a bitfield whose
  payload isn't exactly `ceil(num_pieces/8)` bytes disconnects
  `invalid_bitfield_size` — oversized frames were silently truncated
  before (`bt_peer_connection.cpp:978`).

- **`num_incoming_*` counters bumped exactly once**: the session-
  level `match p.msg` bump duplicated ids 0–8 on top of the torrent
  dispatch funnel; the funnel now owns counting (upstream's
  torrent-attached gate included — messages on dead torrents don't
  count).

- **`num_incoming_ext_handshake` counts only parsed handshakes** —
  moved to the tail of the `id == 0` parse block; a bdecode-invalid
  BEP-10 handshake is swallowed uncounted, as upstream.

- **`hashes_rejected` re-pokes every v2 connection**: a `hash_reject`
  now runs `maybe_send_hash_request` on all `protocol_v2` conns, not
  just the refusing one (`torrent.cpp:7446` parity).
