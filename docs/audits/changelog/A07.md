### Fixed

- **Peer-list source ranking uses the full `peer_source` bitmask
  (audit A07 round-2, D16)**: `compare_peer` and the erase-candidate
  paths now rank `source_rank(p.source)` over the OR-combined source
  mask and test `p.source == RESUME_DATA` as exact equality, matching
  upstream `peer_list.cpp`. A multi-source entry (e.g. `LSD|PEX`,
  rank 20) now correctly outranks a single-source `LSD` entry (16),
  and a `RESUME_DATA|INCOMING` entry is no longer treated as
  resume-data-only for weeding/insert rejects. The
  `primary_source()` helper — which projected the mask onto a single
  bit — is gone; `update_peer_port` now also passes
  `peer_info::incoming` as the source like upstream.

- **Incoming-at-cap evicts the oldest in-flight dial (D17)**:
  `m_connections.end_index() >= limit` upstream — the per-torrent
  cap counts pending dials (conn objects exist from
  `create_peer_connection`), so the admission path now compares
  `peers + num_connecting`. When >10% of `max_connections` are still
  connecting, the longest-waiting dial mark (smallest
  `last_connected`, the `m_connect` analogue) is abandoned via
  `peer_disconnected_addr` — normal severity, dial-cooldown restamp,
  `dial_pids`/`dial_locals`/`num_connecting` settled — and the
  incoming conn takes the slot. Previously the eviction scan ran
  over `t.peers`, which never holds connecting conns, so the
  incoming conn was always killed instead.

- **Connection accounting is live-conn based (D18)**: new
  `Torrent::num_connections()` mirrors upstream `num_peers()` =
  `m_connections.size() - m_peers_to_disconnect.size()` (attached
  non-disconnecting conns plus in-flight dials). It now feeds
  `find_disconnect_candidate_torrent`, `on_accept_fd_exhausted`,
  the exceeded-limit `cand_n > this_n` comparison,
  `update_connections_limit`'s redistribution, the per-tick
  `session_conns` count, and both `peer_turnover` legs — the
  turnover previously sized victims off the peer-list pool, which
  includes never-dialed entries and misses half-open conns.

- **`ListenPort` collision is a normal-severity disconnect (D19)**:
  a duplicate endpoint advertised via the BEP-10 `p` key now emits
  `duplicate_peer_id` at `DisconnectSeverity::Normal` instead of
  `PeerError` — upstream's `disconnect(errors::duplicate_peer_id)`
  defaults to normal, so no more spurious `peer_error_alert`,
  `error_peers` bump, or `failcount` increment.

- **Share-mode recalc precedes conn insertion (D20)**:
  `recalc_share_mode` runs before `add_peer` in `peer_connected`'s
  attach tail, matching upstream `attach_peer`'s
  recalc-then-`sorted_insert(m_connections)` order — the new conn
  no longer inflates the rebalance divisor (e.g. the >50%-seed cull
  or the `share_mode_target` gate) on the attach that triggers it.

- **`ban_web_seeds` gate honored everywhere `ban_peer` runs
  (D21)**: `Torrent::ban_peer`/`ban_peer_at` now refuse `web_seed`
  entries unless `settings.ban_web_seeds`, like upstream
  `torrent::ban_peer` (`torrent.cpp:11918-11926`) — and a real ban
  runs `update_want_peers` + `num_banned_peers` inside the call.
  `apply_smart_ban` and `penalize_peers` gate only the ban itself:
  upstream still posts `peer_ban_alert` and disconnects
  (`peer_banned`/`too_many_corrupt_pieces`) when the ban is refused.
  Both self-connection legs (`m_outgoing_pids` probe and
  `NewConnVerdict::SelfConnect`) route through the gated path.

- **Regression coverage (round 2)**: `test_peer_list` —
  `ranking_uses_full_source_mask` (multi-bit sources outrank
  single-bit) + `resume_data_checks_use_exact_mask`
  (RESUME_DATA|INCOMING survives the capacity reject and the
  should-erase-immediately sweep; the `ranking_uses_primary_source`
  test, whose premise encoded the deviation, is rewritten).
  `test_peer_lifecycle_a07` — `full_torrent_evicts_oldest_pending_dial`
  (oldest dial mark dies, incoming attaches, dial bookkeeping
  settled), `num_connections_counts_live_not_peer_list`,
  `listen_port_collision_is_normal_severity`,
  `share_mode_recalc_excludes_incoming_conn` (pre-insert census
  leaves priorities untouched), `ban_peer_respects_ban_web_seeds`.
