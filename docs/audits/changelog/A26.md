# A26 — DHT

### Fixed

- **dht**: incoming-packet pre-filters ported — datagrams
  `len <= 20` or not shaped `d…e` are dropped before the
  dos-blocker, so non-DHT UDP traffic sharing the port (LSD
  `BT-SEARCH`, tracker noise) no longer consumes the
  per-source rate budget or risks a 5-minute ban
  (`dht_tracker.cpp:517` parity).
- **dht**: KRPC decode limits tightened to upstream's
  `depth_limit = 10`, `token_limit = 500` (was crate defaults
  100 / 2M) — over-wide/over-deep datagrams are rejected like
  upstream.
- **session**: the `ip_filter` is now applied to DHT datagrams
  in `on_udp` (upstream `dht_tracker::incoming_packet` drops
  filtered sources before the blocker).
- **dht**: `sample_infohashes` replies are range-checked like
  `sample_infohashes_observer::reply` (`interval` `0..=21600`,
  `num` `0..=i32::MAX`, `samples` multiple of 20 — malformed →
  observer timeout, no partial data); collected `nodes` are
  delivered to the callback but never traversed. The session's
  direct `dht_sample_infohashes` alert applies the same gate.
- **dht**: `storage.tick()` is gated to once per 2 minutes
  (`m_last_tracker_tick` in `connection_timeout`) instead of
  every node tick.
- **dht**: self-refresh cadence realigned — the extra 5-second
  bootstrap retry on an empty table is removed; `node::tick`
  fires `bootstrap()` only on the 10-minute `depth() < 4`
  self-refresh like upstream.
- **dht**: pending RPC transactions of `flag_done` (cancelled
  or already-answered) observers are dropped at tick before
  timeout dispatch — upstream `rpc_manager::tick` erases them
  without firing a timeout (`RpcManager::drop_tags`).

### Tests

- `test_dht_tracker.rs`: non-DHT datagrams don't consume
  blocker budget; framing rejects short/non-dict packets; KRPC
  token-limit rejection; 2-minute `storage.tick()` gate.
- `test_lookups.rs`: `sample_infohashes` malformed replies
  (missing/out-of-range interval/num/samples) are timeouts;
  valid replies mark `traverse = false`.
- `test_rpc.rs`: `drop_tags` removes matching pending
  transactions only.
- `test_session.rs`: `dht_ip_key_votes_external_ip` packet
  padded past the 20-byte framing floor (upstream drops
  `<= 20` byte datagrams before decode).
