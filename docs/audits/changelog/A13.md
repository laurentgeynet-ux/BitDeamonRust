### Fixed

- **Piece picker bucket index re-cascades on every queue move
  (audit A13)**: `update_piece_state` only re-added a piece to
  `m_pieces` when its computed priority crossed `-1`. Upstream also
  calls `update(prio, index)` for every `prio != -1` outcome — a
  `downloading → full` transition (or `downloading ↔ reverse`,
  which shifts the `-3 → -1` adjustment) now relocates the piece
  instead of leaving it in a stale bucket until the next dirty
  rebuild, matching `piece_picker.cpp:3048-3052`.

- **Share-mode `num_downloaded` counts have-filtered pieces out**:
  `recalc_share_mode` used `num_pieces - num_filtered` where
  upstream takes `want().num_pieces`
  (`- num_have_filtered` too), so filtered pieces we already own no
  longer inflate the share-mode reprioritization gate.

- **Picker loop counters are wired**: `PickerStats` is now
  implemented for `&Counters` (the eight upstream
  `piece_picker_*_loops` slots) and the real counters flow into
  `pick_pieces` at every call site, web seeds included — the
  `session_stats` picker metrics no longer read zero.

- **End-game busy block waits for a fully empty request queue
  (passe 2)**: `request_a_block`'s post-pick gate used the pre-pick
  outstanding count; upstream re-reads `dq.size() + rq.size()`
  *after* the loop, where `add_request` has already pushed this
  pass's picks. A pass that queues free blocks but still can't
  fill `num_requests` no longer also emits the duplicate busy
  request — the busy block stays a true last resort, matching the
  one-busy-per-peer endgame rule.

- **`picker_options()` ports the missing upstream legs (passe 2)**:
  - `initial_picker_threshold` — below the threshold (default 4
    pieces) upstream drops `rarest_first` and picks randomly while
    prioritizing partials; we no longer rarest-first from the
    first block.
  - `prioritize_partial_pieces` — the setting now ORs
    `prioritize_partials` onto any branch.
  - `piece_extent_affinity` — the setting now arms
    `PIECE_EXTENT_AFFINITY` on non-snubbed peers in rarest-first
    mode with no time-critical pieces, enabling the previously
    unreachable extent-affinity pick path.
  - Sequential mode no longer sets `RAREST_FIRST` alongside
    `SEQUENTIAL` (upstream asserts them exclusive) — snubbed peers
    under sequential/sub-threshold no longer pick `reverse`, and
    prioritized partials keep `m_downloads` order instead of being
    rarest-first-sorted.
  - The snubbed-peer replacement pick (`snub_peer`) and the
    in-flight re-mark paths now compute the full per-peer options
    (parole, snubbed→reverse/extent-affinity) instead of a
    hard-coded `rarest_first` base.
