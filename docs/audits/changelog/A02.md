### Fixed

- **`ut_pex` seed flag no longer tautological (audit A02)**:
  `pex_tick` advertised `pex_seed` whenever a conn's bitfield
  covered its own advertised piece count — true even on metadata-
  less torrents. The flag is now `valid_metadata() && c.is_seed()`,
  matching upstream `p->is_seed()` under the torrent-metadata gate.

- **`ut_pex` first list no longer delayed up to 60 s (wire/tempo)**:
  the torrent-global `last_pex` stamp is gone; each conn owns
  `pex_last_msg` (upstream `ut_pex_peer_plugin::m_last_msg`, init
  `min_time()`), so a fresh connection receives its full peer list
  on its first eligible tick once `num_peers() > 1` — the lone-peer
  phase no longer consumes its window.

- **PEX cap bookkeeping**: `build_pex_message` now marks every
  visited eligible conn as seen *before* the `max_peer_entries`
  (100) break — upstream's `m_old_peers.insert` order. A conn
  skipped by the cap is never re-emitted as a phantom `added` and
  never oscillates added↔dropped across ticks.

- **PEX receive caps are per family**: `pex_known`/`pex_known6`
  bound separately at `max_pex_peers`, and a saturated v4 ledger
  skips (not breaks) so trailing `added6` entries still process —
  upstream runs `added`/`added6` in independent loops.

- **`i2p_pex` plugin only on I2P conns; `ut_pex` honors
  `allow_i2p_mixed`**: attach-time extension ids now match
  `create_ut_pex_plugin` (`priv() || (i2p() && !allow_i2p_mixed)`)
  and `i2p_pex_plugin::new_connection` (`is_i2p(socket)`), so a
  mixed-mode I2P torrent gossips `ut_pex` on clearnet conns and
  `i2p_pex` never leaks onto non-I2P sockets.

- **`send_allowed_set` gates on the remote, not us**: upstream's
  `upload_only()` check is the *peer_connection's* (`m_upload_only
  || is_seed() || m_have_all`). Allowed-fast sets now reach
  leechers when we're upload-only and are withheld from seeds and
  BEP-21 upload-only peers.

- **`send_upload_only` runs the full `send_not_interested` legs**:
  interested conns clear `m_interesting`, drop the
  `num_peers_down_interested` gauge, stamp `became_uninteresting`,
  leave slow start and re-run `disconnect_if_redundant` before the
  wire `NotInterested` goes out; uninterested conns jump straight
  to the redundancy check instead of emitting a message.

- **`smart_ban` is operational**: the piece hash job now emits
  per-16KiB-block SHA-1 digests (the bytes were already read),
  propagated through `DiskCompleted::Hash` to
  `on_piece_verified`'s `read_digest` — upstream's `async_read`-per-
  block ledger without extra disk I/O. A peer sending inconsistent
  data for the same block across two failed pieces is banned and
  disconnected.

- **`has_metadata` edges match upstream**: `incoming_interested`
  sets `m_has_metadata` (a peer ready to download has the info
  dict); `incoming_dont_have` does not. Both feed
  `disconnect_if_redundant`'s keep-alive gate in the right
  direction.

- **`lt_donthave`/`DontHave` respect `is_disconnecting()`**: conns
  mid-teardown return before the `invalid_dont_have` bound check —
  no `peer_error` disconnect and no failcount pollution on dying
  connections.

- **`disconnect_if_redundant` gains the `m_disconnecting` early-out
  and the `can_disconnect` plugin veto** (`PeerPlugin::
  can_disconnect`, default `true`) — upstream's extension
  interception point for redundant-conn teardown.

- **`ut_metadata` request gating on `valid_metadata()`**: a v2-only
  torrent (metadata present, no v1 `piece_hashes`) no longer emits
  metadata requests upstream never sends.

- **`ut_metadata` `dont_have` reply carries `total_size` + the info
  dict when held** — upstream writes `total_size` on every
  `write_metadata_packet`, not only on `piece` replies.

- **`num_incoming_pex` counts `i2p_pex` messages without `added`**:
  upstream bumps the counter at the handler tail of any parsed
  dict, peers present or not.
