### Fixed

- **Proxy credentials advertised for non-`*_pw` types (audit A24)**:
  matching `instantiate_connection.cpp`, `set_username` is now only
  applied for `socks5_pw` / `http_pw`. A `socks5` proxy with a
  configured username no longer advertises method 2 nor runs the
  user/pass sub-negotiation, a plain `http` proxy no longer emits
  `Proxy-Authorization`, and SOCKS4 userid stays on the configured
  field only where upstream uses it.

- **SOCKS5 UDP associate loses `BND.PORT` on domain replies**: bound
  replies now carry the parsed bound name, and the relay endpoint
  falls back to the proxy IP + returned port instead of the TCP port
  (`socks_connect` domain leg, upstream `udp_socket.cpp`).

- **Relayed UDP datagrams accepted from any source**:
  `Socks5UdpSocket::recv_from` now drops packets not originating from
  the relay endpoint, like upstream's source check in the wrap/unwrap
  path.

- **UDP tracker hostnames resolved locally under a SOCKS5 proxy**:
  new `DatagramSocket::send_hostname` sends `UdpTarget::Name` as
  SOCKS5 ATYP 3 through the relay when `proxy_hostnames` is set,
  matching upstream `udp_socket::send_hostname` — no local DNS
  leakage.

- **UDP proxy gating was all-or-nothing per lane**: sends now carry
  `DatagramSendFlags` distinguishing peer / tracker / unclassified
  usage and honor `proxy_peer_connections` /
  `proxy_tracker_connections` per datagram, matching upstream's
  per-`flags` decision in `udp_socket::send`.

- **`socks5_udp_send_local_ep` parsed but dead**: the UDP ASSOCIATE
  request now sends the socket's local endpoint when the setting is
  enabled (upstream still defaults to `0.0.0.0:0`).

- **Dead SOCKS5 UDP relays went unnoticed**: the control TCP is now
  monitored — closure tears down the association — and connect uses a
  10 s timeout plus bounded retry with upstream's backoff
  (`min(120, f²/2) + 5 s`), so a dropped control connection no longer
  leaves a silently dead lane.

- **SOCKS5 CONNECT to an unspecified address waited on the wire**:
  `0.0.0.0`/`::` numeric destinations are now rejected
  (`UnspecifiedEndpoint`) before any handshake I/O, matching upstream
  `socks_connect`'s `invalid_argument` leg.
