### Fixed

- **Web-seed fetches bypassed the bandwidth manager entirely
  (audit A28)**: upstream `web_peer_connection` is a
  `peer_connection` — its HTTP reads go through `setup_receive` →
  `request_bandwidth(download_channel)`, so seed traffic consumes
  the same class quota as peers. The pull-model fetch loop now wraps
  the injected stream in a throttling layer (`ThrottledWs`): each
  read/write is clamped to the granted quota, an empty bucket queues
  `Session::request_bandwidth_web` and parks on the grant
  (`bw_limit`), and every transferred chunk accrues IP/TCP overhead
  on both directions (`trancieve_ip_packet`). `download_rate_limit`,
  per-torrent `set_download_limit`/`set_upload_limit` and the
  mixed-mode proportional split now apply to url-seed traffic like
  upstream.

- **Web-seed peer classes resolved from the resolved endpoint**:
  `request_bandwidth_web` computes the conn-side class mask via
  `peer_class_mask(addr, FilterSocketType::Tcp)` — a public seed
  lands on `global|tcp`, a private/link-local one picks up `local`
  like an attached conn would; a proxy-held hostname falls back to
  the public-TCP set. Request priority is the max over the mask's
  classes and the torrent's class set (`peer_connection::get_priority`).

- **Web-seed overhead and teardown semantics**: the fetch handle
  registers on the torrent (`web_seed_bw`) so `second_tick` drains
  its `ip_overhead` accumulators into both the conn-side class mask
  and the torrent class set (`use_quota_overhead`), posting
  `download_limit_too_low`/`upload_limit_too_low` under
  `rate_limit_ip_overhead` exactly like wire peers. A torn-down
  fetch marks the handle `disconnecting` on every exit path, which
  drops it from the drain immediately (upstream: conn erased from
  `m_connections`) and lets `update_quotas` release its queued
  request and return the assigned quota.

- **`http_conn`/`fetch_block` generalized over the stream type**:
  `send_request`/`recv_response`/`http_get`/`fetch_block` now take
  `S: AsyncRead + AsyncWrite + Unpin` instead of `&mut
  BoxedPeerStream`, so rate-limiting wrappers can sit under the read
  path (callers unchanged — `BoxedPeerStream` satisfies the bounds).
