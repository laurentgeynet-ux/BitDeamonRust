### Fixed

- **NAT-PMP never attempted PCP (audit A25)**: `start_natpmp` now
  emits 60-byte PCP MAP requests first like `natpmp::start`
  (`m_version = version_pcp`), with per-slot nonces, and falls back
  to NAT-PMP only on `pcp_unsupp_version` received over a non-v6
  socket — resending the outstanding request and firing the opcode-0
  public-IP query then, not before.

- **Silent NAT-PMP gateways caused unbounded re-sends**: mappings
  created at `Instant::now()` were re-emitted every tick forever.
  Requests are now tracked (`outstanding_request` + `map_sent`),
  retransmitted on upstream's `250 ms * retry_count` linear backoff,
  abandoned at 9 retries, and a mapped slot renews at
  `lifetime * 3/4` (was `lifetime / 2`); error replies park the slot
  for 2 h like upstream's `expires = now + hours(2)`.

- **NAT-PMP mappings leaked on shutdown**: `stop_natpmp` now sends
  the ttl-0 delete datagram per mapped slot before dropping the
  state, and both `stop_natpmp`/`stop_upnp` run when the service is
  disabled mid-session.

- **Router IP vote fired on the public-IP reply alone**: the
  `source_router` vote now rides the mapping's external address at
  `on_port_mapping` success — PCP reply field, or NAT-PMP's
  `m_external_ip` — matching upstream's deferred vote.

- **UPnP leases were never renewed and lease settings ignored**:
  the engine tick now sweeps `renew_due` per slot (re-add at
  `expires`), `UpnpDriver` is constructed with
  `upnp_lease_duration`, and `start_natpmp` honors
  `natpmp_lease_duration` — 3600 was hard-coded in both places.

- **`upnp_ignore_nonrouters` had no effect**: SSDP replies from
  hosts outside the local network are now dropped (the local subnet
  is approximated from the datagram socket's bound address — v4 /24,
  v6 /64 — where upstream enumerates interface netmasks).

- **`NewInternalClient` empty on user-requested UPnP mappings**:
  `portmap_add` now passes the device's local address like upstream
  `map_port` does.

- **UPnP `close()` queued deletes for unresolved devices**:
  devices without a resolved control URL are skipped verbatim
  (upstream's close loop).

- **LSD accepted announces from outside the LAN**: inbound packets
  are now gated by `match_addr_mask` against the listen socket's
  address/netmask, matching `lsd::process_packet`.

- **LSD announced once per cycle instead of ×3**: each announce is
  re-sent at +2 s and +4 s via `lsd_resends` (upstream's
  `resend_announce` timer).

- **LSD announced the bound port, not the mapped one**, and only
  the v1 hash: announces now use the socket's `tcp_external_port()`
  (SSL sockets for SSL torrents) and iterate `info_hashes()` so
  hybrid torrents emit both the v1 and truncated v2 hash.

- **LSD peers never triggered `do_connect_boost`** and the i2p
  gate was missing: `on_lsd_peer` now rejects private/i2p-non-mixed
  torrents and immediately dials the discovered peer via
  `do_connect_boost` with `inc_boost_connections` accounting.

- **External-IP voting was global instead of per listen socket**:
  `vote_external` now targets `listen_socket_t::external_address`
  (same-family socket, `accept_incoming` preferred; session voter
  as fallback), and a changed consensus additionally runs upstream's
  `new_external_ip` effects — `clear_peer_prio` on every torrent and
  `dht.update_node_id` (BEP-42) — besides the `external_ip_alert`.
