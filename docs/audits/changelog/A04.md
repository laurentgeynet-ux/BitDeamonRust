# A04 — Trackers (HTTP/UDP announce, scrape, backoff, tiers)

### Fixed (round 2 — residual deviations)

- **session**: `prioritize_udp_trackers` rewritten to upstream
  semantics — a `udp://` entry now *swaps* with the first earlier
  non-udp entry serving the **same hostname**, across tier
  boundaries (`tracker_list.cpp:100-132`); it is actually invoked at
  the torrent ctor and `replace_trackers` under
  `prefer_udp_trackers` (was dead code before, with wrong
  intra-tier semantics).
- **session**: `stop_tracker_timeout <= 0` now suppresses the whole
  stopped-announce leg (`announce_with_tracker` returns before any
  work) — no phantom `TrackerError`/`fails++` on pause.
- **session**: `send_tracker_request` stamps `next_announce =
  min_announce = now` at dispatch — a stale tracker `min interval`
  no longer delays the post-failure retry cascade.
- **session**: `add_tracker` marks `need_save_resume
  (if_metadata_changed)` on real insertion and both
  `add_tracker`/`replace_trackers` run `announce_with_tracker()`
  immediately when the torrent is announcing (effects routed via
  `pending_out` for handle calls).
- **session**: `set_session_paused` now aborts in-flight
  non-stopped announces *before* flagging torrents session-paused —
  each abort runs `announce_skipped` bookkeeping (fails++, message,
  alert, failover cascade) like upstream `abort_all_requests`, and
  a `sent_seq` request identity makes the late completion of an
  aborted exchange drop stale.
- **session**: `trackerid` is carried as raw bytes end-to-end (was
  lossy UTF-8), `trackerid_alert` fires only when the id actually
  *changes*, `warning message` lands on the endpoint's `message`
  slot, dict-peers carrying our own `peer_id` are skipped, scrape
  replies no longer mark the tracker `verified`, `ipv4`/`ipv6`
  announce params are populated for private non-anonymous torrents
  from the listen sockets, forced by-idx announces honor
  `announce_trackers`, and the failure cascade propagates
  `high_priority`.
- **net/engine**: UDP tracker replies from a source endpoint other
  than the target are ignored (`m_target != ep`), resolved
  endpoints are family-filtered symmetrically for the bound
  datagram socket, `stopped` announces resolve DNS `cache_only`
  (no shutdown stall), and the UDP `num_want`/WS announce path now
  clamps `numwant` to `max_webtorrent_offers`, always emits the
  `offers` array, short-circuits `num_want == 0` as
  `torrent_aborted` without connecting, and maps tracker `failure
  reason` to a 120 s retry hint.
