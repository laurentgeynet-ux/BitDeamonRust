# A27 — Engine glue

### Fixed

- **bitdaemon**: `Engine::tick` no longer drains the alert queue —
  `run()` dropped the `pop_alerts()` return, so every alert raised
  during normal operation was destroyed before
  `SessionHandle::pop_alerts`/`wait_for_alert` could see it.
- **bitdaemon**: completion channels (`gone`, `connect`, `udp`,
  `announce`, `web-seed`, DHT-node/UPnP) are serviced by dedicated
  `run()` arms as they land — upstream runs each handler directly on
  the io_context. Dead-peer block refunds and dial attaches no longer
  wait out the 500 ms `tick_interval`; each `select!` arm forwards
  its consumed head item into the shared drain.
- **bitdaemon**: acceptor head-of-line removed — each accepted
  connection's responder handshake (plain + SSL acceptors) runs on
  its own task bounded by `handshake_timeout`, matching upstream's
  self-driving `peer_connection`. A silent peer can no longer wedge
  the accept loop for everyone else.
- **session**: `SessionHandle::add_torrent_params` routes its
  `SessionOut` effects into `pending_out` instead of dropping them —
  `.torrent` `nodes` now reach `DhtAddNode`.
- **bitdaemon**: `last_second_tick` primed to `now - 900ms` at
  construction (`m_last_second_tick(m_created - 900ms)` upstream) —
  the first heavy second-tick fires ~100 ms after start.
