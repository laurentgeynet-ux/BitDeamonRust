### Fixed

- **`AddTorrentParams.root_certificate` now drives SSL-torrent
  detection and trust (audit A23)**: `is_ssl_torrent()` /
  `ssl_root_cert()` prefer the add-time `root_certificate` override
  over the embedded `ssl-cert` — a torrent carrying only
  `root_certificate` is now correctly an SSL torrent, matching
  `torrent.cpp` (`init_ssl` prefers `atp.root_certificate` and marks
  `m_ssl` whenever either source is present). Engine SSL params pick
  up the selected root.

- **Inbound mutual TLS is pinned to the SNI-resolved torrent**:
  `ssl_accept_torrent` now uses rustls `LazyConfigAcceptor` to read
  the ClientHello, resolve the hex-encoded info-hash SNI to a
  torrent, and install *that torrent's* client-cert verifier
  (`torrent.cpp` `set_context` on `ssl_stream`). A client certificate
  valid for some *other* registered torrent is no longer accepted.

- **Attach-time `invalid_ssl_cert` legs**: an SSL torrent presented
  with a peer connection that has no SSL context, or whose SNI
  info-hash resolves to a different torrent than the BitTorrent
  handshake, now fails with `invalid_ssl_cert` instead of attaching.

- **`peer_error_alert` (`op = ssl_handshake`) on inbound TLS
  failure**: upstream posts `peer_error_alert` from the SSL accept
  path; the accept task now reports handshake errors to the session
  instead of silently dropping the connection.

- **Certificate alerts at the `init_ssl` point**:
  `TorrentNeedCert` is posted when an SSL torrent initializes
  without a configured cert/key (upstream fires it at `init_ssl`,
  not at `set_ssl_certificate`), and invalid PEM cert/key input on
  `set_ssl_certificate{,_buffer}` produces `TorrentError` +
  `invalid_ssl_cert` like `ssl.cpp`.

- **`validate_https_trackers` honored**: when false, HTTPS tracker
  exchanges use a verify-none TLS client config (upstream
  `session_impl::m_ssl_ctx` verify-none for tracker requests).

- **HTTPS announces of SSL torrents use the torrent's TLS context**:
  tracker requests for an SSL torrent now verify through the
  torrent's own root (`req.ssl_ctx`) rather than the system root
  store.

- **SSL announce/DHT port**: announces for SSL torrents now send
  `port = ssl_listen_port` (`torrent.cpp:2958`), and DHT announce
  port resolution for SSL torrents falls back to the SSL listen port
  instead of `listen_port` when `port == 0` (implied ports are
  forbidden for SSL torrents).

- **Outbound SSL SNI uses the peer's info-hash version**: dialing an
  SSL peer now encodes the v1 or v2 hash matching the negotiated
  protocol version instead of always the v1 hash.

- **Stale SNI registrations removed**: `refresh_ssl_certs` rebuilds
  the SNI→torrent map and trust-root map from scratch, so removing
  a torrent drops its cert serving entry and trust root
  (`unregister_ssl_torrent`).

- **CLI socket types**: `start_ssl_acceptor_at` now reports kind 6
  (tcp_ssl) and SSL uTP kind 9 (utp_ssl) instead of 1/6 — inbound
  SSL connections from the example client are no longer rejected
  with `requires_ssl_connection`.
